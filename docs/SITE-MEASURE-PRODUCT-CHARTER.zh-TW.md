# Site Measure Studio｜產品方向與設計憲章

> **核心定位：為石材現場量尺深度定製的參數化 CAD 工具。不是通用 CAD，也不只是畫圖筆記。**  
> **核心體驗：像筆記一樣自由、快速；在背後運用幾何約束與量尺知識提高精度，而不增加使用負擔。**

建立：2026-11-16  
性質：**長期產品方向／設計決策基準**，不是不可修改的規章。當真實使用驗證出更好的方向，應明確修訂本文件並記錄原因。

## 1. 真正要解決的問題

現場量尺時，使用者拿著手機或 Android 平板，經常沒有網絡，時間有限，需要能快速畫出 Kitchen、Bathroom Vanity、Island 等簡單或不規則的 countertop 形狀，填寫實測尺寸，標註 OPEN／牆面、Sink Center、Overhang 與必要備註，隨時回看並輸出簡潔的 PDF／DXF。

軟體是否被高頻使用，首先取決於**順手、直覺、打開就能用、操作成本低**。技術深度與介面複雜度不必相同。

## 2. 不可輕易丟失的設計原則

### A. 自由記錄，非阻斷式驗證（Non-blocking Validation）

- 不以缺少工程名、深度、角度、Sink Center、某條邊或其他尚未量到的資料為理由讓整個工具「罷工」。
- **可以且應該提醒缺了什麼**。相較於普通筆記，主動發現缺失與矛盾是本工具的優勢；優先在圖形／尺寸附近輕量提示，而非強制彈窗。
- 使用者可以只量一部分，稍後繼續；可以先畫、先記、先匯出含未完成標記的現場資料。
- 資料不足：顯示暫定輪廓、未確認狀態或「?」，保留所有已量資訊。資料矛盾：保留原始實測值並指出衝突，不替使用者默默改數據。
- **重要分界**：編輯與現場記錄儘量不中斷；將資料認定為「已確認的製造幾何」時不能假造尺寸。未解決的幾何不應被靜默匯入可直接切割的 CNC 輪廓。這是準確性分級，而不是拒絕讓使用者工作。

### B. 即開即用、毋須想著保存

- 參考華為筆記的體驗：隨時開始，隨時停止，隨時查看舊紀錄，不要求進行「先命名、先建立完整工程、先按保存」的儀式。
- 新工程可以自動取名、可隨時改名；操作與輸入即時自動保存。保存狀態可以可見，但不打斷。
- 沒有網絡也可以開啟、編輯、保存、查看既有工程，並在裝置上生成 PDF／DXF。
- **Auto-save 不等於安全備份**。需有清楚、可靠的本機備份／恢復路徑；避免瀏覽器資料意外清除導致全部工程消失。

### C. 場景導向的參數化 CAD，不做通用 CAD

- **保留 CAD 的幾何精度與約束能力，去掉需要使用者操作傳統 CAD 指令的負擔。**
- 規則來自石材量尺的真實需求，逐步增加，例如 OPEN／牆側、固定基準邊、相鄰邊垂直、前後平行、不同邊長形成偏斜形狀、局部不規則牆面。
- 不必一開始建立全功能 Constraint Solver；先實現可靠的常用形狀與高頻場景，藉使用反饋擴展。
- 約束能被修改、解除與重新定義。規則必須幫使用者少做操作，不應把使用者困在模板裡。
- 幾何不足以唯一確定時，**不可從部分數字假裝求出了確定形狀**；暫定形狀仍可畫，明確保留未知條件。

### D. 極低介面摩擦，畫布為主角

- 平板端一次輸入最好只佔一至兩行；點尺寸直接改數值；避免狹窄的小對話框被軟鍵盤擠走。
- 功能盡可能直接作用於畫布；使用者不應先背熟工具層級、操作模式或過多按鈕。
- 減少重複入口及誤觸。例如 Edge Treatment 單點操作與批量 Paint 的關係，應由現場使用判斷是否精簡。
- 標註符合現場空間語義：Overhang 在哪側，算式的呈現及方向應能對應圖上位置；左右垂直尺寸要易於順勢閱讀。
- 增加新能力，理想情況下**不增加更多必要點擊和對話框**。不要因功能深度而讓介面變深。

### E. 漸進式精度與不失真的資料語義（Progressive Precision）

- 可從粗略輪廓開始，隨測量值和約束增加而逐漸收斂；區分 **實測**、**推導**、**暫定**、**未知**。
- 畫布自由線、Wall Sketch、Canvas Note 可記錄現場觀察，但不自動等同精確牆體幾何／切割輪廓。
- PDF 是**以圖形與圖上尺寸為主**的精簡 Field Drawing，而非每邊毫米數值長表／說明書；能保留未完成資訊與必要警示。
- 將來輸出正式可加工 DXF 時，應清楚區隔未確定及已確認的輪廓；不默默用猜測數據填補。

## 3. 一個核心場景：Bathroom Vanity 前後差 1/4″

現場先有 Back = 100″、Front = 100.25″，並逐步設定前／右側 OPEN 與相關垂直、平行或基準邊條件。

- 使用者填第一個尺寸，工具立即保留並顯示；不等資料齊全才讓人開始。
- 填第二個尺寸，工具能提示「Front/Back 相差 1/4″」，但**不自動宣稱哪側牆斜了**。
- 若另有足以確定形狀的平行／90°／基準位置和深度資訊，求出相符的梯形或其他輪廓。
- 如果尚未唯一確定，允許暫定顯示，輕量標記缺什麼，並可繼續量 Sink、Note、下一個 Part。
- **OPEN 是現場邊緣狀態，不天然代表某條幾何約束**；約束應由已知場景規則或使用者明確確認導入。

**我們要的是「使用者記錄現場，軟體逐步理解」，不是「使用者先滿足軟體全部要求才准畫圖」。**

## 4. 平台與工程策略

### Offline-first 是產品要求，不只是快取功能

- 目標是工地完全斷網仍能使用，包含**首次／冷啟動條件的可用性**、現場全流程、保存、PDF/DXF 與資料恢復。
- 目前 Web/PWA 有 Service Worker、IndexedDB 與離線資源準備，但「Offline ready」字樣不是完整斷網驗證。
- Android APK 是合理的中長期方向；優先研究共用 TypeScript 幾何核心與 UI 的封裝（例如 Capacitor），**不可只做依賴網站連線的 WebView 外殼**。是否採用原生技術以實際測試決定。
- 不要因此過早雙線重寫 Web 與 Android。

### 降低開發成本，保留交付品質

- Commander 月額度只有 10,000 次。往後盡量 GitHub 分支 + Codex/自動測試 + Vercel Preview，Commander 留給必要的本機 Windows 工作。
- 真實平板操作與工地案例優先於想像中的需求；先用、收集摩擦點、再做小步迭代。
- 變更量尺／幾何核心要回歸舊工程資料、撤銷與恢復、PDF／DXF 一致性；不要因新功能犧牲既有準確性。

## 5. 發現偏航時如何拉回

每次討論功能或 UI，先檢查：

1. **真實場景：** 它是從哪個實際量尺動作或問題出發？
2. **操作成本：** 能否更快、更直覺？是否增加了不必要按鈕／設定／彈窗？
3. **非阻斷：** 資料不齊時，使用者能否繼續工作並保留資訊？
4. **幾何真實：** 已量、推算、暫定是否清楚區分？是否偷偷替人決定尺寸？
5. **離線與資料安全：** 無網時是否仍可工作？存檔與備份是否可靠？
6. **專用而非通用：** 這是在服務石材現場，還是在複製一個用不到的通用 CAD 功能？

**這不是禁止改方向。** 當現場實測或產品試用證明新的做法更好，可以修改方向；但應記錄「原則、遇到的實例、為何改變」，不要讓局部 UI 決策悄悄取代長期定位。

## 6. 已確認與待驗證

### 已確認的產品方向

- 深度定製石材量尺工具，有場景化參數化 CAD 能力，非通用 CAD。
- 直覺、低摩擦、高頻使用是第一優先。
- 可以合理提醒缺失或矛盾，**不應因未量完而拒絕使用**。
- 自動保存、自由開關與查看歷史；最終需要可靠的完全離線方案。
- PDF 圖與尺寸為主；資料和製造幾何不可混淆。
- Commander 呼叫成本需要控制，開發方式更偏 GitHub/自動化。

### 待以實機與工地驗證的具體設計（不是已交付承諾）

- Sink Center 等輸入從鍵盤會擠壓的小視窗改為少量欄位、鍵盤上方可用的平板輸入列。
- 垂直尺寸閱讀方向及 Overhang 算式依實際伸出側排列。
- Edge 單點 Paint 與批量 Paint 是否需要保留兩個入口。
- 參數化約束的資料模型、基準邊語義、何時把暫定幾何轉成精確幾何。
- PWA 斷網冷啟動與 Android APK 的可靠性驗證。
- Note／Wall Sketch 用真實場景持續迭代，而非先把它們設計成複雜工具。

**讓使用者自由量、隨手記、繼續做；讓軟體在背後理解、提醒、求解與保存。功能要更深，操作要更輕。**
