# Site Measure Studio — 現場量尺草稿工具規劃

> **狀態：Planning / 尚未開發**  
> **討論日期：2026-10-31**  
> **網站：** [baicai.dev](https://baicai.dev)  
> **候選路由：** `/tools/site-measure`  
> **首要設備：** Android 平板 + Chrome（觸控）  
> **文件目的：** 保留需求緣由、已確認的決策、第一版範圍與驗收標準，供後續 Codex 和人員逐步實作、測試與修訂。  
> **注意：** 此文件為開發規劃，不代表功能已存在、已測試或已部署。

## 1. 這個想法從哪裡來

最初討論的是另一個想法：可以在 iOS/Android 查看、量測、輕量編輯既有 DXF 的 **Mobile DXF Viewer / Editor**，曾研究 MLightCAD 等 GitHub 開源方案。

討論現場作業時，出現了**新的、獨立的需求**：

- 工廠目前去客戶家量 countertop，會用 iPad 的筆記軟體畫大概的 Rectangle 或 L 形，再用手寫尺寸註解。
- 這些只是「手稿」：畫的線與輸入的尺寸**沒有幾何關聯**，比例不準確；回工廠還需要重新整理 AutoCAD。
- 使用者希望在 Android 平板打開一個極簡網站工具，選擇常見的**形狀模板**、填入實際測量的數字、寫備註，就得到**尺寸控制的 2D 草稿**，可保存、日後繼續改、輸出標準 DXF 交給 AutoCAD。
- 首要成功標準：**現場用起來比原來的筆記軟體方便**；不追求第一版功能龐大，也不要求當場生成 CNC 加工成品圖。

**不要混淆專案：** Site Measure Studio 不是原先的「打開既有 DXF 進行通用編輯」工具；前者以**模板建立新量尺稿**為主，後者以 DXF Reader/Editor 為主，可在將來視需求整合，但初期無依賴。

## 2. 已確認的產品方向

1. **形式：** 網站內的輕量、觸控優先工具；先支持 Android + Chrome，後續可考慮 PWA、iOS、桌面。
2. **使用方式：** 開啟網站 → 建立量尺工程 → 選擇 Rectangle / L-shape 模板 → 輸入量到的尺寸 → 預覽等比例幾何 → 增加 sink/stove 位置與備註 → 保存工程 → 匯出 DXF → 回工廠用 AutoCAD 校對、調整。
3. **圖形生成：** 手指負責選擇、調整大致位置；**數值決定幾何**，不能只把數字當成繪圖旁邊的文字。
4. **範圍控制：** 第一版先做少數最常用模板；實際量尺幾次後，再依真實需求增加模板和工具，**不要預先做成完整 AutoCAD**。
5. **Leica 的角色：** Leica X4/X6 的現場量測座標、Leica Fit Studio 是**另外的精密量測輔助流程**，幫助回工廠確認 Wall、Corner 和角度。**不是**本工具第一版的輸入依賴；不應因為提到 Leica 就合併專案。
6. **正式圖紙責任：** 現場工具生成的是**真實、數值定義的 CAD 幾何**，並非只能畫比例失真的示意圖。對資訊完整的簡單 Rectangle / L-shape，可在通過幾何及製程檢核後，直接交給 True Form Studio 等後續工具，**不一定要經 AutoCAD 重新繪製**；但「幾何正確」不自動等於「可安全加工」。不能宣稱未經驗證的輸出即可直接進 CNC。
7. **名稱：** Site Measure Studio 是工作名稱，可再調整。

## 3. 代表性的真實使用情境（來自討論）

同一位客戶家有三個區域：

- **Bathroom 1：** 矩形 vanity top，量長、深，標 sink 位置。
- **Bathroom 2：** 第二個矩形 vanity top，同樣快速輸入尺寸。
- **Kitchen：** stove 左邊有一塊小型 countertop；右邊有一段 L-shape countertop、一個轉角和 sink 位置。
- 現場記錄 countertop 各段長度/深度、sink / stove 位置、backsplash / overhang 等備註；回工廠後用 AutoCAD 和其他量測資料作最終調整。

設計含義：一個量尺工程應能放**多個區域**，每個區域應能放**一個以上的形狀**；但可分階段實作，避免第一版過重。

## 4. V0.1 — 最小可用版本（必須）

### A. 基本工程與區域

- 新建、命名、重新開啟量尺工程；至少能區分多個區域（Kitchen、Bathroom 1、Bathroom 2）。
- 各區域可添加多個獨立的 countertop 草稿形狀。
- **保存的是可編輯的結構化工程資料**（模板類型、參數、座標、備註、區域與待確認狀態），不能只保存圖片或只保存輸出的 DXF。
- 第一版優先本機保存；提供可攜帶的工程檔備份 / 匯入，避免只依賴瀏覽器快取。離線能力必須另外驗收，不可默認已有。

### B. 模板幾何

- **Rectangle**：輸入長度和深度，立即得到數值對應的真實比例幾何。
- **L-shape**：用清楚的必要尺寸定義外框及凹角，驗證尺寸關係，能顯示左右方向／轉向；缺少必要尺寸時提醒，不能憑空推算成已量得數據。
- 支援一個區域放多個模板，分別改尺寸，不互相誤改。
- 預設直角只是一個**設計假設**；對未確認的牆角可標示「待確認」，不可把顯示為 90° 當成實測結果。

### C. 現場標記與備註

- 可以添加 **sink center / stove / cooktop 位置參考**；**sink 只要中心點／中心線與定位尺寸，不需要畫出 sink cutout**。實際水盆輪廓及切孔可在 True Form Studio 的後續工作流程處理（該功能是否已完成須以當前程式實測確認）。參考點／線不可誤當作已驗證的開孔加工輪廓。
- 每個區域／形狀可添加自由文字備註，記錄 backsplash、overhang、wall、cabinet 等。
- 清楚區分「實測尺寸」、「暫時假設／待確認」；讓回廠的人知道哪些地方需要複核。

### D. Android 平板的操作體驗

- Chrome 直接使用；大面積畫布、簡單模板選單、大觸控目標、少量明確操作。
- 支援雙指縮放、平移、Fit All、形狀選取；數字鍵盤輸入尺寸，圖形立即更新。
- 對輸入錯誤、空值、負數、尺寸互相矛盾給出明確反饋。
- Undo / Redo 或其他可靠的操作復原機制；修改、切換區域、關閉頁面前應避免意外資料遺失。
- 橫向平板優先，兼顧直向小螢幕。不能依賴滑鼠 hover 才能發現功能。

### E. DXF 匯出與回廠流程

- 匯出**可由 AutoCAD 開啟、後續編輯**的 2D DXF，不是 raster image / PDF 偽裝。
- 使用真實幾何座標，單位在匯出中明確定義；以 mm 作為內部基準，未來可加入英寸輸入與顯示。
- 圖形、註記、不同區域／形狀的資料應可區分（合理分 Layer 或清楚群組）。
- 第一版**不承諾**反向讀入並無損編輯任意既有 DXF；那是另一項工作。
- 必須在 AutoCAD 實際重開、量距與檢查輪廓。**DXF 格式可寫出，不等於幾何已能投入 CNC**。

## 5. 明確不做（V0.1 Non-goals）

- 不開發通用 CAD 全套 LINE / ARC / OFFSET / TRIM / BLOCK 編輯器。
- 不整合 Leica Fit Studio，不解析 Leica 2DG / CSV 作自動 countertop 輪廓。
- 不做複雜 Wall 校正、非直角多邊形自動求解、掃描點擬合。
- 不做 CNC Toolpath、不做 production-ready Parts、自動決定 overhang / polished edge / miter。
- 不需要客戶帳號、遠端雲端同步、伺服器保存客戶 DXF 或住址。
- 不把未完成驗證的量測幾何直接視作可以下料的加工圖；也不強制所有簡單幾何重畫 AutoCAD。
- 不修改 ZOLITH Studio、True Form Studio、Leica Fit Studio 的既有功能。

- 評估瀏覽器端儲存（例如 IndexedDB）加「匯出／匯入工程檔」；預設本機處理，對資料保留風險給用戶明確提示。

## 7. 技術策略 — 重用開源，但保持輕量

- **自己設計**模板參數模型、觸控交互、工程儲存與現場流程。
- **優先重用成熟的小型 DXF writer** 而非從零造 DXF 文件格式；候選 `@tarikjabiri/dxf`，採用前要驗證版本、授權、輸出 DXF 的 AutoCAD 相容性。
- **MLightCAD** 等通用 DXF Viewer 是先前 DXF Reader/Editor 想法的候選，**不必作為量尺工具 V0.1 的依賴**。只有在實際需要讀取複雜既有圖紙時，才評估其整合與授權／包體成本。
- 模板產生的是基於統一幾何數據模型的形狀；不要為每個模板維護一套互不相容的儲存格式。
- 重要數值用可預測的單位轉換及座標計算處理，顯示捨入不可反向損失底層數據。

## 8. 首次實測與驗收

請優先用一個**假資料**工程做端到端驗證，不把未審核現場資料交給 CNC：

1. 在 Android 平板 Chrome 建立工程，包含 Kitchen、Bathroom 1、Bathroom 2。
2. Bathroom 各建立一個 Rectangle，改長／深後預覽確實等比例變化；不是只改標籤文字。
3. Kitchen 建立一個小 Rectangle 和一個 L-shape；能自由選取和分別修改參數。
4. 標記 sink、stove 和幾條備註；能把待確認的尺寸／轉角清楚標註。
5. 保存工程、關閉 Chrome、重新打開；形狀、數值、備註都未丟失。
6. 將工程檔另存/備份，在新瀏覽器會話中重新匯入並得到相同內容。
7. 輸出 DXF，在 AutoCAD 打開；量得的長度／深度與輸入相同、單位正確、輪廓能編輯、備註可辨識。
8. 驗證放大縮小不改幾何尺寸；錯誤尺寸或不完整 L-shape 不會偷偷生成看似已確認的成品輪廓。
9. 用真正的 Android 平板實際完成一次現場量尺，回顧**是否比原來的筆記軟體更快、更清楚、更容易回廠整理**。

**成功準則：** 以上基礎操作可靠，且現場使用體驗比既有筆記流程明顯更好；不以功能數量作為成功標準。

## 9. 建議實作節奏（非已授權開始開發）

- **Phase 0 — 技術 Spike：** 用最小 demo 驗證 Rectangle/L-shape → 真實幾何 → DXF → AutoCAD；量測單位、L-shape 參數及 DXF round-trip 先跑通。
- **Phase 1 — Android 可用原型：** 區域、模板、尺寸修改、觸控、備註、保存/重新開啟、匯出 DXF。
- **Phase 2 — 現場回饋：** 實際量尺多次，修掉操作摩擦，確定新增模板優先級。
- **Phase 3 — 視需求擴充：** U-shape、Island、特殊 vanity、更多標註、離線安裝／跨平台或與 Mobile DXF Viewer 的有選擇整合。

## 10. 待實測再決定的問題（不應阻塞第一個原型）

- 現場最常用的尺寸單位／輸入習慣（mm、inch、英寸分數）及顯示格式。
- sink/stove 標記所需的最小數據：中心點、對牆距離、可選大概輪廓？
- L-shape 預設方向、凹角參數命名與是否允許鏡像。
- 工程備份的檔名及副檔名；是否需要附照片（第一版暫不做）。
- 畫面最舒服的操作布局：先選模板再輸入參數，或先大概畫出形狀再改參數。
- 哪些尺寸需要「實測／待確認」標記及匯出時如何辨識。

這些優先透過真實 Android 平板使用來驗證，不必現在猜到完美。

## 13. 2026-10-31 新增確認：精確幾何與可略過 AutoCAD 的簡單工作

使用者特別糾正先前「只是草稿」的說法。**本工具的 Rectangle / L-shape 應是標準幾何**，數值驅動且真正按比例，不是純示意塗鴉。稱為「量尺草稿」是指**尚未完成加工核准的流程狀態**，不是說 DXF 的幾何數據不精確。

### 工作例子：Vanity

- 現場量得長 **60 inch**、深 **22 1/2 inch**；**sink center 從一側量到 30 inch**。
- 這組例子的幾何矩形必須是真實尺寸（**1524 × 571.5 mm**），sink 的長向參考中心位置為 **762 mm**。尚未提供前後向（Y）定位尺寸時，**不可自行推斷或繪製實際 sink center 點／sink cutout**；可顯示 X 向中心線和「Y 待量」。
- 使用者沒有要求在量尺工具畫 sink 形狀；sink cutout 可能由未來的 **True Form Studio** 選型／放置功能負責。此能力屬後續期望，不可記成現有已驗證功能。
- 圖紙若已符合尺寸、單位、閉合輪廓等要求且加工資訊完整，有機會**略過 AutoCAD 手工重畫**，直接進 True Form Studio，再流向 ZOLITH Studio／Pegasus。但每個整合環節需實際測試相容性和安全性，並保留人工加工審核。

### 建議區分「幾何」與「生產狀態」

- **Measured geometry：** 已輸入的精確外輪廓和座標，DXF 可保存；不等於牆面、櫃體或加工工序全部已確認。
- **Reference geometry：** sink center X 向中心線、stove 位置、備註；清楚放在 Reference/Annotations Layer，**不是 cutout**。
- **Readiness check：** 真實尺寸、單位、輪廓閉合、無自交、方向、幾何是否完整、參考資訊與切割資訊是否混淆；特別是加工邊、overhang、物料厚度、實際 sink 型號及加工策略仍待工廠確認。
- **Output：** PDF 方便分享現場量尺內容；DXF 保留原生幾何，供 AutoCAD／True Form Studio／下游 CAD/CAM 驗證和繼續工作；結構化工程檔用於回到網站修改。

### 保留舊工作工具的優點（正式列入 V0.1）

- **Auto-save：** 編輯時自動本機保存，不用每次按 Save；建議 IndexedDB，仍必須可匯出／匯入工程備份。瀏覽器清除網站資料／儲存被回收可能造成資料遺失，不應假裝是雲端永久保存。
- **PDF Export + DXF Export：** **兩者都是 V0.1 核心輸出**。PDF 呈現尺寸、中心線與備註，DXF 保留真實數值幾何；不應先只做 DXF 而忽略分享與現場查看。
- **File management：** 工程列表、建立／命名／重開，基本備份還原；先在設備本機運作，不要求註冊和伺服器儲存。
- **Input：** 面向 Android 或 Huawei 平板的 Chrome/相容瀏覽器，手指和觸控筆都應可用。裝置與瀏覽器能力需在真機驗證；有 Chrome 不代表所有設備的檔案／PWA 功能完全相同。

### 新增驗收案例

1. Rectangle 輸入 60\" × 22.5\"，幾何長寬必須在 AutoCAD 讀取為 1524 × 571.5 mm（若內部 DXF 以 mm 為單位）。
2. Sink Center X = 30\" → 762 mm 的參考中心線，**不輸出水盆輪廓、不憑空決定 Y**。
3. 檢查 PDF 與 DXF 的數字、比例與備註一致，不能在輸出時改變幾何尺寸。
4. 完整關閉／重啟平板瀏覽器後可恢復工程；清除網站儲存前可匯出工程檔備份。
5. 用真實 True Form Studio 版本驗證簡單幾何 DXF 可否接受和進一步製作 Part；未通過的環節不得標示為自動直通 CNC。
