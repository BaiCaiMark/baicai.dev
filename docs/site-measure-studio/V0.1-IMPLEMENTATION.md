# Site Measure Studio V0.1 Preview

Implementation authorized 2026-10-31. This is an editable field-measurement prototype, not manufacturing approval. Historical product decisions remain in PRODUCT-PLAN.zh-TW.md and DECISIONS-2026-10-31.md.

## Run and try

From the repository root:

```powershell
npm ci
npm run dev -- --hostname 127.0.0.1 --port 3012
```

Open http://127.0.0.1:3012/tools/site-measure. Choose **先試示範工程**, then **Bathroom 1**. The cabinet is 59 × 21 inch, with right allowance 1 inch and front allowance 1.5 inch: finished geometry is 60 × 22.5 inch (1524 × 571.5 mm). Sink X is 30 inch from the finished left edge; Y is deliberately unknown.

For a blank job: create project → add Rectangle → enter W/H → explicitly set unused edges to 0 → apply end/front preset to chosen edges → add Sink or Cooktop → enter reference measurements → download an editable project backup and PDF/DXF.

The toolbox entry remains Draft and the tool route has noindex metadata. A feature-branch Preview does not change production.

## Architecture and data integrity

- Route: app/tools/site-measure/page.tsx (server metadata); Studio.tsx owns client interaction.
- core/model.ts: strict, versioned schema, measurements, presets and sample-only fixture.
- core/units.ts: decimal mm/inch and proper/mixed inch fractions; no permissive numeric coercion.
- core/geometry.ts: one authoritative calculation pipeline, polygon validation, references and measurement report rows.
- core/history.ts: grouped edits, bounded in-session Undo/Redo.
- core/storage.ts: Dexie/IndexedDB, atomic project + previous version, optimistic concurrency.
- core/export-pdf.ts and core/export-dxf.ts: lazy-loaded adapters consuming a fixed project snapshot.
- components/: SVG viewport and reusable quantity entry. No customer-data API or server action.

A Quantity stores original input and input unit, origin and confirmation independently. Dimension/reference fields expose a measured/assumed selector; editing an assumption retains its assumed origin. Blank/invalid input stays editable and recoverable but cannot produce a finished outline. Numeric values are parsed into mm; display conversion does not modify saved input. Numerical geometry assertions use 1e-6 mm tolerance, not floating-point equality. This numerical tolerance is not a claim of field measurement accuracy.

Origins are measured/default/allowance/assumed; calculated results are derived, not editable measurements. A confirmed preset never becomes a measured value. Explicit 0 is valid; blank is unknown. No cabinet door thickness is added.

Project defaults are suggestions until applied to a specifically selected edge. Each applied quantity copies its value, status and preset revision. Editing defaults never updates existing shapes.

Cabinet and finished measurement modes retain separate input sets. Switching modes never relabels cabinet readings as finished readings. When both input sets define complete but contradictory outlines, final geometry/DXF export is blocked until reconciled. Inactive readings are included in the report.

## Geometry and references

Canonical coordinates are X right and Y toward the front. Rectangle vertices are (0,0), (W,0), (W,H), (0,H). L vertices are (0,0), (W,0), (W,A), (B,A), (B,H), (0,H), requiring 0 < A < H and 0 < B < W.

Stable edges are:
- E1/back: first edge.
- E2/right: right end.
- E3/front: bottom end.
- E4/left: left side.
- E5/innerX and E6/innerY: L return edges.

L perimeter order is E1, E2, E5, E6, E3, E4. Each edge moves along its outward normal; adjacent orthogonal lines are intersected. Self-intersection, degeneracy, and edge reversal are rejected. Topology-changing offsets, negative allowances, arbitrary polygons and non-right-angle solving are unsupported.

Rotation and reflection happen after solving and preserve edge identities. Left/right/back/front reference labels refer to the original template frame and transform with the shape; output includes orientation, with X+/Y+ guides for transformed shapes. The 90-degree template assumption has a separate confirmation status.

Sink/cooktop coordinates are explicitly relative to cabinet or finished bounding edges and a selected direction. A single known axis creates clipped reference line(s), not a full center point. A center is drawn only when both supplied coordinates lie within the reference polygon. No cutout is generated.

Workspace placement is deterministic page layout only, never a surveyed relationship. Pan, zoom and Fit All change viewport state only. DXF converts the SVG-style Y-down frame into CAD Y-up coordinates without changing dimensions.

## Outputs and recovery

PDF uses vector geometry and embedded Noto Sans TC (SIL OFL; see public/fonts/site-measure/OFL.txt). It includes cabinet/top distinction, applied allowances, composition equations, original measurement provenance/status, references, notes and warnings. Long notes paginate. Unsupported glyphs fail visibly instead of silently disappearing. The self-hosted font is 7,149,140 bytes and loads only for PDF export; first export requires the asset to be reachable. Sample PDF is approximately 130 KB because only used glyphs are embedded. No screenshot-only output or browser print dependency.

DXF uses real closed LWPOLYLINE, LINE and TEXT entities, mm INSUNITS, and SM_TOP / SM_CABINET / SM_REFERENCE / SM_DIM / SM_NOTES layers. Unicode notes use DXF escapes; a suitable CAD font is still required on the receiving machine. Incomplete shapes are listed before export and in DXF exclusion notes; zero valid outlines disables DXF. References are not cutouts. Drawing layout coordinates are not site coordinates.

IndexedDB saves during editing, with background/pagehide flush as an additional measure. Successful status appears only after an atomic write. Quota/error states retain current edits and expose backup/retry/save-copy controls. Multi-tab stale writes fail rather than overwrite. New project imports always get a new project ID; imports are schema-validated and limited to 5 MB / 200 shapes per project. Previous saved version can be opened as a new copy.

Only completed writes can be recovered after a process kill; unsaved keystrokes cannot be guaranteed. Browser clearing/eviction and private browsing may remove data. Project backups are essential. Preview and production storage are separate origins. There is no cloud backup or offline/PWA guarantee.

## Pending acceptance and scope limits

- Android/Huawei real hardware, stylus/palm behavior, on-screen keyboard, file picker/download and field speed comparison are **pending**. Desktop Chrome/CDP is not hardware acceptance.
- AutoCAD open/edit/measure/Unicode font compatibility is **pending**. An independent parser is not AutoCAD acceptance.
- True Form Studio/CAM/CNC/operator acceptance is **pending and outside this implementation**.
- No arbitrary DXF import, freehand CAD, sink cutouts, non-orthogonal walls, U templates, cloud accounts/sync or PWA/offline caching.
- Undo/Redo history is in-session; durable recovery provides the previous saved revision and portable backups.
- Very many shapes may need zoom or selection; no field-performance claim is made without target-device testing.
- Same-origin third-party scripts can access browser data. The production site previously injected a Cloudflare beacon; Preview/runtime request inspection is required independently of this app having no upload code.
